# Почему SDM, а не просто агент?

Агент с моделью (харнес) умеет «делать»: написать онтологию, вопросы, экспорт — выглядит так же.  
SDM добавляет то, что голый агент дать не может: **фиксированное определение правильности и проверяемость**.

## Без SDM

Агент на вопрос «чего не хватает в профиле?» отвечает исходя из своего разумения — это **мнение** конкретной модели в конкретном контексте.

- Непроверяемо — нет формулы, по которой вычислен ответ
- Невоспроизводимо — другой агент (или тот же через час) даст другой список
- Нет порога — «вроде достаточно» vs «вроде маловато» каждый раз на глаз
- Нет аудита — нельзя сказать «между версией 3 и 4 в профиле изменилось вот это»

## C SDM

| Свойство | Как работает |
|---|---|
| **Детерминизм покрытия** | Одинаковые ontology + profile → одинаковый список gap у любых реализаций (инвариант 1). Сравнение — `diff` двух прогонов, они идентичны побайтово. |
| **Машинная самопроверка** | `sdm doctor`, `validate`, `coverage` ловят обрывы ссылок, невалидные kind, веса ≠ 1, циклы в графе — до того, как дефект ушёл в экспорт. |
| **Пороги и критерии** | «Профиль пройден, когда у каждого навыка ≥3 вопросов И depthRatio ≥ 0.9» — зафиксировано, не на глаз. |
| **Аудит через git** | Артефакты — спеки: диффы, история, ревью. «Что изменилось между версиями?» — `git diff`, не переспрашивание модели. |
| **Один скелет → много поверхностей** | Экспорты (MCP/Obsidian/веб/CLI/тест/курс) из одного источника. Без SDM каждый экспорт — ручная сборка. |

## Итог

| С SDM | Без SDM |
|---|---|
| `❌ ontology-concept: achievedDepth=0, questions=0` | «Мне кажется, чего-то не хватает» |
| `diff` двух прогонов — идентично | Никак не проверить |
| Порог 0.9 / 3 вопроса — зафиксирован | «Ну, штук 5, наверное…» |
| Любой инструмент → тот же результат | Зависит от контекста модели |

Агент с моделью — **исполнитель**, который умеет всё.  
SDM — **эталон и линейка**: что считается правильным и как это проверить.

## Демонстрация

```bash
# Два независимых прогона покрытия — результат идентичен
sdm cert coverage --profile sdm --level current --json > run1.json
sdm cert coverage --profile sdm --level current --json > run2.json
diff run1.json run2.json  # → пусто: побайтово совпадает
```

Голый агент на тот же вопрос даст разные ответы от прогона к прогону.
