# Планы этапов SDM

## Этап 1: Ребрендинг и комиссия (12.09 – 24.09)

**Цель:** подготовить доклад к защите перед комиссией (24.09), публичный ребрендинг SDM → SDM.

| Задача | DoD | Критерий приёмки |
|---|---|---|
| Создать структуру `sdm/` | Директория с README, docs, plans, ADR | ADR-000 зафиксирован, нейминг нигде не перепутан |
| Написать одностраничник SDM | Один .md файл с описанием методологии (что, кому, слои, инварианты, чем не является) | Человек без контекста может объяснить методологию другому без «покажи код» |
| Ребрендинг SDM → SDM (код + имена + манифест) | core/cli/mcp работают под именами `@spec-driven-methodology/*`, бинарники `sdm` | `sdm --version` и `sdm-mcp` запускаются |
| Собрать HSE-демо | Онтология HSE-курса, профиль, coverage, gap-ы | Демо показывает рабочий pipeline за 3 минуты |
| Прогон на руководителе | Руководитель прослушал доклад, три ответа: понятно/убедительно/что не так | Получена обратная связь, доклад скорректирован |
| Заявка на PGConf подана | Текст заявки, тезисы | Согласовано с комиссией |

## Этап 2: Полный ребрендинг (24.09 – 16.11)

**Цель:** завершить технический ребрендинг, подготовить Postgres-демо, провести конференцию.

| Задача | DoD | Критерий приёмки |
|---|---|---|
| npm публикация `@spec-driven-methodology/*` | Все пакеты опубликованы | `npm install @spec-driven-methodology/cli` работает |
| GitHub org `spec-driven-methodology` активна | Репозитории: methodology, sdm-core, sdm-cli, sdm-mcp | Ссылки не ведут на старый SDM |
| CHANGELOG без sdm | История изменений переписана без слова sdm, функциональность сохранена | Сравнение версий корректно |
| Postgres-онтология и профиль | ontology тем Postgres, профили DBA/Developer/Analyst | Coverage показывает gap-ы |
| Выступление на PGConf | Доклад 20-30 минут, демо live | Зал может назвать методологию, а не только инструмент |

## Этап 3: Экосистема (после 16.11)

**Цель:** сделать SDM платформой для сторонних kit-ов.

| Задача | DoD | Критерий приёмки |
|---|---|---|
| Плагинная архитектура в `sdm-core` | API для сторонних команд и схем | `postgrespro-sdm` и `hse-sdm` собраны без форка ядра |
| Conformance-тест | Набор fixture-данных + тест «одинаковые ontology/profile → одинаковое gap-множество» | Две реализации на одних данных дают одинаковый результат |
| Вебсайт методологии | spec-driven-methodology.org (или GitHub Pages) | Там же: одностраничник, ADR, ссылки на реализации |

## Принципы выполнения этапов

- Этап N не требует завершения этапа N-1 для старта отдельных задач (например, Postgres-онтология может начаться до полного ребрендинга).
- Граница между этапами — «готово для кого»: этап 1 = готово для комиссии, этап 2 = готово для конференции, этап 3 = готово для мира.
